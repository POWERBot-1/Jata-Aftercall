## Evidence conventions / verdict rules

A `PASS` below means source wiring or a named automated test exists; it is not a browser acceptance pass. A `NOT TESTED` means there is no current-turn user-interaction evidence. The required individual-control fields are represented by route family, visible-label examples, intended action, handler/backend, auth/entitlement and user feedback. Dynamic lists, per-template controls and all screen-reader/keyboard states require enumeration by a live browser and remain out of scope here. Do not interpret an untested control as working.

## Concrete source-level observations

- `app/install/page.tsx` contained a customer-facing label pointing to the Vercel deployment despite linking to `/`; changed to the official public URL.
- `lib/qr.ts` defaulted to unrelated `https://jata.co.ke`; changed to the official domain and added tests for fallback/configured/explicit origins.
- Existing screenshot `docs/agents/evidence/landing-320x568.png` (described in its README as a local public-page browser capture) shows the mobile marketing nav truncating the final “Install” label at the right edge; the desktop counterpart shows the full nav. CSS now prevents nav anchors from shrinking and permits the mobile flex row to wrap; a regression contract test was added. The candidate SHA `0cd537d` six-viewport real-Chrome workflow passes, but its artifact could not be downloaded for pixel review; visual post-fix state remains unreviewed.
- Four reproduced source/UI defects are therefore addressed (three stale URL references plus the narrow-screen nav clipping); no claim is made that all other dead controls were exhaustively ruled out.
- Static searches cannot determine whether a conditional branch is visible, whether a form submits successfully, whether a click produces an honest result or whether a control is keyboard-operable. A real browser session with isolated seeded accounts and the approved test services remains necessary.
