## 2. How the evidence was produced (exact commands)

Sandbox prerequisites: `npm ci` (already run); a Chromium binary was obtained locally from the
npm registry package `@sparticuz/chromium` with `npm install --no-save`, its Lambda shared-library
tarballs were extracted to `/tmp/al2libs/lib` and `/tmp/al2023libs/lib`, and `LD_LIBRARY_PATH` was
set to those directories. `@sparticuz/chromium` is **not** a committed dependency; the committed
scripts use the already-installed `puppeteer-core` and a `CHROME_PATH` environment variable.

```bash
# Dev server for contact-action / marketing captures (no database, offline Prisma stub).
ARENA_LIVE_PREVIEW=1 AUTH_SECRET=local-evidence-secret npm run dev   # http://localhost:3000

LD_LIBRARY_PATH=/tmp/al2libs/lib:/tmp/al2023libs/lib \
CHROME_PATH=/tmp/chromium BASE_URL=http://localhost:3000 \
node scripts/browser/contact-actions-evidence.mjs

# Production build for PWA evidence. The sandbox cannot download Prisma engines, so the four
# pre-existing tests/prisma type errors were bypassed ONLY for this local build by temporarily
# adding tests/** to tsconfig.json exclude; tsconfig.json was restored immediately afterwards.
AUTH_SECRET=local-evidence-secret npx next build --webpack
npx next start -H 0.0.0.0 -p 3001

# Phase 1: worker registration and cache inspection while the server is running.
rm -rf /tmp/jata-pwa-profile docs/evidence/pwa-evidence.json
LD_LIBRARY_PATH=/tmp/al2libs/lib:/tmp/al2023libs/lib \
PWA_PHASE=prime CHROME_PATH=/tmp/chromium BASE_URL=http://localhost:3001 \
node scripts/browser/pwa-evidence.mjs

# Phase 2: stop `next start`, then exercise a GENUINE network failure. Chrome DevTools offline
# emulation does not apply to fetches made inside a service worker, so a stopped server is used.
LD_LIBRARY_PATH=/tmp/al2libs/lib:/tmp/al2023libs/lib \
PWA_PHASE=offline CHROME_PATH=/tmp/chromium BASE_URL=http://localhost:3001 \
node scripts/browser/pwa-evidence.mjs
```

`AUTH_SECRET=local-evidence-secret` is a throwaway local value, not a production credential. No
production environment variable, key, token, cookie, customer record or database row was read or
written by these scripts. No screenshot contains a secret.

**Automation boundary.** Chrome reports `null` instead of an HTTP response for navigations served
by a service worker when `navigator.webdriver` is set. The repository's real-database browser
harnesses assert `response.status === 200`, so `components/pwa/PwaInstaller.tsx` deliberately
skips service-worker registration in automated browser contexts. Real users still receive the
PWA. `pwa-evidence.mjs` explicitly overrides `navigator.webdriver` to `false` before page load,
so the PWA evidence below measures the real registered service worker rather than a bypass.

## 4. Honest limitations — read before treating any screenshot as production proof

- **NOT VERIFIED (production):** the screenshots are from a local build of the working branch, not
  from `https://jata-aftercall.vercel.app`. The sandbox has outbound access only to GitHub and
  package registries; both `curl` and Chromium navigation to the production host failed with a
  connection error. Production was inspected only through read-only text fetches.
- **BLOCKED (baseline screenshots):** genuine before-change screenshots of the live production
  application could not be captured for the same egress reason. The pre-change state is documented
  from read-only production text (placeholder demo numbers, text-only actions, homepage note that
  “No demo page is currently available to open”) and from `main` source inspection. No claim is
  made that a visual baseline was captured.
- **Fixture, not production data:** `/dev/contact-actions/[slug]` renders the real public
  `BusinessPage` component with the four fictional `lib/demoData.ts` fixtures and the new
  read-only `resolveDemoContacts()` fallback. These routes are development-only
  (`process.env.NODE_ENV === "production"` returns 404). They prove the renderer and its
  destinations, **not** the content of the production database rows.
- **No database:** the local build uses the repository's offline Prisma stub. Authenticated
  journeys, payment verification, media upload, subscription settlement, webhook idempotency and
  cross-tenant database writes were **NOT TESTED** in this evidence set; they are covered by
  repository unit/integration tests and CI gates only where explicitly recorded in the owner
  report.
- **NOT TESTED:** real Android/iOS installation, Google Play / App Store artefacts, custom-domain
  HTTPS, transactional email delivery, durable R2 storage and live JATA Qi integration. No such
  claim appears in these artefacts.
- **No production change:** no merge, no deploy, no DNS/storage/env change, no payment, no store
  submission and no production data write was performed.

## 5. Reproducibility and integrity

- Screenshots are unedited Chromium viewport captures. Their filenames encode viewport and page.
- `browser-evidence.json` and `pwa-evidence.json` contain raw measurements, console output and
  cache inventories; the summary booleans are derived from those measurements, not hand-written.
- Re-running the scripts regenerates the same file names; because timestamps and chunk hashes
  differ, byte-identical output is not expected.
- The scripts exit non-zero if any objective check fails. They were run with every check passing
  for the recorded final state.
