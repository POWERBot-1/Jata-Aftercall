## 4. Principal findings

**Severity:** High. At the baseline, media upload, PATCH and single/bulk delete called `guardTenantMutation` without an explicit write action, so a VIEWER could pass the read-level gate. The local code now requires `configure` for all four mutations; `GET` remains read-only. **Evidence:** E-06 and full tests in E-11. Route authorization uses mocked tenant/Prisma data; authenticated staging remains untested.

### F-02 — Media metadata could be overwritten by stale edits

**Severity:** High. The baseline PATCH used an unconditional update. The local fix adds a defaulted integer version, tenant-scoped conditional `updateMany`, atomic increment, conflict response, and UI draft retention. Identical-pixel reuse uses CAS when it changes metadata. The client sends `expectedVersion`; omission remains accepted for old callers, limiting stale-snapshot detection for those callers to pre-existing behavior. Mocked handler regressions are current; an earlier checkpoint recorded isolated PostgreSQL direct-SQL CAS, not reproduced in the final checkpoint. No Prisma-generated SQL, Neon, or production evidence exists. **Evidence:** E-07, E-16, E-18.
